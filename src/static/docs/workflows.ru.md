# Workflow

Workflow — это программа из блоков, которая лежит в [пакете](/docs/packages). Его триггеры запускают прогоны; каждый блок делает что-то одно (HTTP-запрос, вызов Discord, заметку, значение в хранилище) и передаёт результат следующему.

## Включение

Триггеры workflow запускают прогоны, только пока включено **Запуск по триггерам**. Ручной запуск (**Запустить**, с входом в JSON) работает в любом случае.

## Триггеры

- **ManualTrigger**: вручную или когда его вызывает другой workflow пакета.
- **WebhookTrigger**: POST на его адрес с заголовком `X-Webhook-Secret`, равным его секрету; тело в JSON становится входом прогона. На странице workflow виден адрес и, по запросу, секрет; **Новый секрет** заменяет его (старый сразу перестаёт работать). Что получает вызывающий:
    - _Immediately_: сразу 202 с id прогона;
    - _OnFinish_: ждёт конца прогона и получает выход последнего блока (500, если прогон упал);
    - _ByBlock_: ждёт блок RespondToWebhook и получает то, что он отправит.
- **ScheduleTrigger**: расписание cron (пять полей) в часовом поясе workflow или вашем.
- **События Discord**: событие одного из ваших подключений Discord.
- **ErrorTrigger**: в error workflow пакета, когда падает автоматический прогон пакета.

## Прогоны

Каждый прогон хранится какое-то время: статус, что его запустило, сколько он длился и, пока сервер его хранит, результат (выход, переменные, ошибки). Прогоны workflow видны на его странице, прогоны всех workflow пакета — в разделе пакета _Прогоны_.

## Версии

Каждое изменение программы — новая версия (хранятся последние 50). Старую версию можно восстановить: она станет текущей как новая версия поверх, ничего не теряется. Workflow или одну из его версий можно экспортировать в файл, который импортируется на любом сервере EchoPhase.
