# Пакеты

Пакет объединяет workflow, которые работают вместе, как репозиторий объединяет код. Каждый workflow лежит ровно в одном пакете.

## Что пакет даёт своим workflow

- **Вызовы.** Workflow может запустить другой workflow того же пакета (блок ExecuteWorkflow). Он указывает его по _ключу_: ключ не меняется при переименовании и одинаков во всех установленных копиях. Workflow других пакетов вызвать нельзя.
- **Хранилище.** Блок Storage хранит значения между прогонами: свои у workflow (область _Workflow_) или общие для всех workflow пакета (область _Package_). Другие пакеты их не видят.
- **Ошибки.** Один workflow пакета может обрабатывать упавшие прогоны: когда падает автоматический прогон (webhook, расписание, событие) любого из них, запускается его ErrorTrigger с тем, что упало и почему. Выбирается в настройках пакета.

## С чего начать

- **Новый пакет** на странице «Пакеты» создаёт пустой пакет; импортируйте в него workflow из файлов экспорта.
- Импорт workflow без выбранного пакета создаёт для него отдельный пакет с тем же названием.
- Установка пакета из [Обзора](/docs/explore) создаёт ваш пакет с его workflow.

## Публикация

Пакет остаётся вашим, пока вы не опубликуете его _версию_: неизменную копию его workflow, которую другие читают и устанавливают. Следующая публикация создаёт новую версию, старые остаются.

Вы выбираете, какие workflow войдут в версию (сначала отмечены все). То, что вызывает выбранный workflow, и error workflow пакета тоже должны быть выбраны: иначе у установившего будет вызов в никуда, и публикация не пройдёт.

Секреты webhook'ов в версию не попадают. Всё остальное в блоках (например, API-ключ в заголовке) публикуется как есть.

## Кто его видит

- **Приватный**: вы и те, с кем вы поделились (по имени пользователя).
- **По ссылке**: любой вошедший пользователь, у которого есть ссылка.
- **Публичный**: все, пакет есть в Обзоре.

Меняется в настройках пакета, в разделе _Видимость_. Другие видят только опубликованные версии; ваши workflow в текущем виде остаются вашими.

## Удаление

Удаление пакета удаляет его workflow с их версиями, расписаниями и хранилищем, а также опубликованные версии. Пакеты, которые другие установили из него, остаются у них.
